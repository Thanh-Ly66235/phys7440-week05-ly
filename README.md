# Week 5 — Tool-Augmented Physics Agent with MCP (Thanh Ly)

To reproduce the results from a fresh clone (or the unzipped submission), `cd` into this folder and create a clean Python 3.13 environment (3.12 also works), for example `python3 -m venv .venv && source .venv/bin/activate` or `conda create -n week05 python=3.13 && conda activate week05`. Install the pinned dependencies with `pip install -r requirements.txt`; `requirements-lock.txt` is the exact `pip freeze` of the Linux x86_64 environment. Supply your Anthropic API key by running `cp .env.example .env` and replacing `your-key-here` with your own key (optionally change `ANTHROPIC_MODEL`). `.env` is git-ignored and read through `python-dotenv` by both the notebook and the server, so no key is ever hard-coded. The server itself needs no key, because SIMBAD and arXiv are public. The notebook strips every `*_API_KEY` variable from the server's environment, and the server parses only its own three optional settings from `.env`, so the key never reaches the server process. You can test the MCP server on its own with `python mcp_server_week05_ly.py --list-tools`, which prints the JSON Schemas of `query_simbad` and `search_arxiv`, and `python mcp_server_week05_ly.py --check`, which makes one live SIMBAD and one arXiv query. You never have to start the server by hand: `week05_ly.ipynb` launches it as a subprocess speaking MCP (JSON-RPC 2.0) over stdio, using the kernel's own interpreter (`sys.executable`) and the notebook folder as working directory, so no path needs editing. Run `python mcp_server_week05_ly.py` without arguments only to serve MCP to another client; it then waits for JSON-RPC messages on stdin. Next, start `jupyter notebook` (or `jupyter lab`) in this folder, open `week05_ly.ipynb` and choose *Kernel → Restart & Run All*, or run it headless with `jupyter nbconvert --to notebook --execute --inplace week05_ly.ipynb`. Every agent run is logged to `agent_runs/<label>.json` (question, model, the model's text at each turn, every tool call with its arguments and full result, the final answer and token usage; for the two main runs also the claim-by-claim verification), and the server's stderr goes to `logs/mcp_server_stderr.log`. Keep `agent_runs/` with the notebook; it is not git-ignored, so commit it. Later executions then replay those logs instead of calling the API, so the notebook runs top to bottom without an API key and reproduces the analysed agent runs and checks exactly. Section 1 still queries SIMBAD and arXiv directly, which needs internet access but no key, so its arXiv listing can show newer papers. Set `FORCE_RERUN = True` in the setup cell to query Claude, SIMBAD and arXiv live again. Section 6 writes the observed behaviour of each failure mode into the marked blocks of `week05_failures_ly.md`, so that file always matches the logged runs.

**Environment.** Python 3.13 on Linux x86_64 with `mcp` 2.3.0 (the official MCP Python SDK; in 2.x `FastMCP` is called `MCPServer`, and tools are still registered with `@server.tool()`), `astroquery` 0.4.11 (SIMBAD TAP), `astropy` 8.0.1, `pyvo` 1.9.1, `arxiv` 4.0.1, `anthropic` 1.11.0, `python-dotenv` 1.2.4, `pandas` 3.0.6 and `jupyter` 1.1.1 / `ipykernel` 7.4.0 / `nbconvert` 7.17.1; see `requirements.txt` and `requirements-lock.txt`.

**LLM model and caveats.** The agent uses Anthropic's `claude-haiku-4-5-20251001`, a dated snapshot, so the model weights do not change underneath the results; the verifier in Section 5.3 uses the same model. The Messages API in `anthropic` 1.x exposes no temperature setting, so live runs are not deterministic: the order of tool calls, retries after errors (failure modes F1–F2) and the wording of the summaries can differ between runs. The cached logs in `agent_runs/` are the reproducible record. Another model, set through `ANTHROPIC_MODEL`, may behave differently in the failure cases, e.g. it may silently correct the misspelled name in F1 or answer from memory in F2. Dated snapshots are eventually retired (see Anthropic's model-deprecation page), so switch to a current model if the API rejects this one. The external data also change: arXiv returns newer papers over time, so a re-run with `FORCE_RERUN = True` will usually analyse different abstracts than the 2026-10-13 snapshot described in Section 5.3, and SIMBAD values can be revised.

**Files.** `mcp_server_week05_ly.py` (MCP server with the two tools), `week05_ly.ipynb` (agent loop, Betelgeuse and Proxima Centauri runs, plausibility checks, failure triggers), `week05_failures_ly.md` (failure-mode report), `agent_runs/` (logged runs, created by the notebook), `requirements.txt`, `requirements-lock.txt`, `.env.example`, `.gitignore`.
